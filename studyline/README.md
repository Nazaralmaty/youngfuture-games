# StudyLine — прототипы

Всё здесь открывается по ссылке на телефоне: один HTML-файл на прототип,
без сборки, без CDN, без логина. Данные — в `localStorage`.

**Одна ссылка на всё:** [`index.html`](index.html) — стенд с прямыми ссылками
на состояния (вторая эпоха, режим куратора, экран проигравшего, клан после распада).
[`_pokaz/`](_pokaz/) — страница показа «что было → что стало» со скриншотами.

## Перед показом — одна команда

```bash
node check.mjs            # все прототипы
node check.mjs klan nish  # только названные
```

Открывает каждый прототип в настоящем Chrome на экране 390×844, гоняет его
собственный `?test=1`, ловит ошибки консоли и упавшие ресурсы. Плюс проверяет
то, чего не умеет ни один внутренний тест: страница не должна ездить вбок,
не должно быть `<a>` внутри `<a>`, битых картинок и мёртвых ссылок на стенде.

Сейчас: **231 проверка, 0 проблем.**

Если `puppeteer-core` не установлен — один раз:
```bash
npx -y puppeteer-core@23 --version
```

## Общее для всех прототипов

- **Палитра и токены одни и те же** (`--green`, `--ink`, `--paper`, радиусы, `--ease`) —
  взяты из Figma-файла study_line. Прототипы должны выглядеть как одно приложение.
- **Никаких выдуманных чисел.** Если данные приходят с сервера, они помечены
  константой с комментарием, а не подделаны под правдоподобные.
- **Что не сделано — написано.** В каждом README есть раздел «Что осознанно
  не сделано»: это дешевле, чем объяснять на показе, почему чего-то нет.

## Общее ограничение

Всё работает на одном устройстве. Прогресс, банк вопросов, фотографии
и списки кланов уезжают на сервер отдельной работой — до этого показывать
«100 деңгей» посторонним нельзя: **ответы видны в исходнике страницы**.
